## 你将获得

你只需交付一个静态 Web 应用，其余由应用商店提供：

- 托管你的构建产物，或嵌入你自己的 HTTPS 网站
- 支持发现、评价、评论、投票和分享的商店页面
- 已登录的用户，应用中无需编写任何认证代码
- 以 USDC 支付的一次性应用内购买和月度订阅
- 按用户的键值存储、事件记录和分数排行榜
- 需用户同意的跨应用生物特征评分
- 前台提醒和应用内反馈渠道

---

## 你可以省去的工作

| 原本需要自建 | 商店代为处理 |
| --- | --- |
| 认证、会话、钱包 | 用户登录商店。你的应用永远看不到他们的身份或会话。 |
| 结账和支付处理 | 商店负责结账并记录所有权，你只需读取权益。 |
| 存档和设置的后端 | [`app-state`](/cn/apps/platform/app-state) 和 [`app-metrics`](/cn/apps/platform/metrics-and-scores) 为你存储按用户的数据。 |
| 生物特征数据的同意流程 | 商店在自己可信的界面中展示同意提示，并在服务器端强制执行。 |
| 托管、CDN、TLS | 上传 `.zip` 即可。商店会在独立的每应用源上提供服务。 |

---

## 你的应用如何运行

你的应用运行在一个拥有独立源的沙箱 iframe 中。它无法访问商店的 Cookie、用户的钱包或商店的后端。它所需的平台能力都通过一个小型 `postMessage` 桥接完成，`@elata-biosciences/app-*` 包已为你封装好。参见[宿主桥接](/cn/apps/platform/host-bridge)。

## 构建步骤

<Steps>
  <Step title="创建骨架或集成 SDK">
    使用 `npm create @elata-biosciences/elata-demo my-app` 从模板开始，或将 SDK 添加到现有应用中。参见[你的第一个应用](/cn/sdk/tutorials/first-app)。
  </Step>
  <Step title="检查要求">
    确保你的构建产物满足[要求](/cn/apps/build/requirements)，包括真正使用 SDK 以及包含 `index.html` 入口。
  </Step>
  <Step title="添加 elata.json">
    在 [`elata.json`](/cn/apps/build/elata-json) 清单中声明版本号。
  </Step>
  <Step title="发布">
    按照[构建应用向导](/cn/apps/build/launch-your-app)完成发布。
  </Step>
</Steps>
