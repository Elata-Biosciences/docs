有效的订阅计划将控制您的整个应用程序。 Elata 在打开应用程序之前会检查访问权限，因此您不需要在其中包含订阅结账代码。您还可以出售 [一次性物品](/cn/apps/platform/in-app-purchases)；他们的所有权是分开的。

<Info>
付费结帐需要部署的付款配置。请参阅 [直播内容](/cn/overview/status)。应用程序订阅结账使用连接的钱包在 Base 上支付 USDC 并手动续订；它不是自动定期收费。
</Info>

<a id="configure-your-plan"></a>

## 配置您的计划

打开 **我的应用程序 → 您的应用程序 → 编辑 → 商务 → 每月订阅**。

| 设置 | 行为 |
| --- | --- |
| 每月价格 | 正数 USDC；在表格中输入人类可读的金额 |
| 免费试用 | 0 到 365 天的整数； 0表示没有试用 |
| 活跃 | 非活动计划不会限制应用程序或提供续订 |

每个应用程序都有一个计划。使用计划自己的操作进行保存。所有者和授权团队成员可以对其进行管理。价格编辑不会重写之前记录的付费周期；进行新结帐时请查看当前价格。

<a id="who-gets-access"></a>

## 谁有权访问

| 用户 | 访问 |
| --- | --- |
| 应用程序所有者或授权团队成员 | 无需购买应用程序套餐即可访问 |
| 具有有效付费期限的用户 | 覆盖期间访问 |
| 拥有有效试用期的用户 | 访问直到试用结束 |
| 没有任何这些的用户 | 计划生效时有订阅提示 |

由于没有活动计划，该应用程序可以免费进入。这些规则涉及应用程序访问；他们不授予付费应用内项目。

<a id="the-customers-flow"></a>

## 客户的流量

1. 用户从应用程序的页面或锁定的播放屏幕打开应用程序的订阅提示。
2. 如果符合条件，他们将开始免费试用。当钱包和支付配置准备就绪时，付费结帐可以直接在订阅提示中运行，或者用户可以继续 **设置 → 计费 → 订阅**。
3. 他们选择当月或下个月的可用保险并查看购物车。
4. Elata 在付款后检查结算并记录访问情况。可以在一个购物车中支付多个应用程序。

期间使用 UTC 日历月。下个月的承保范围从第一个月开始；当月的追赶访问（如果提供）将使用购物车中显示的承保范围和按比例分配的价格。试用结束时不会导致自动收费。

用户必须完成结账才能续订。未付费的购物车选择不会扩展访问权限。如果下个月不付费，付费访问就会过期；删除购物车选择不会退还已付款的期限。

之前的 `/profile/subscriptions` 路由重定向到当前的 [计费 → 订阅](https://app.elata.bio/settings/billing/subscriptions) 页面。

<a id="earnings-and-subscribers"></a>

## 收入和订阅者

付费应用程序期间保留其付款金额。 **Commerce** 报告将这些订阅付款显示为扣除分流费之前的总收入。您的份额将直接结算到创建者的支付钱包中。请参阅 [收入和支出](/cn/apps/operate/revenue-and-payouts)。

该计划的订户数量是一个访问信号，而不是精确的经常性收入指标。试验可以有助于当前期间的计数。

<a id="test-before-enabling"></a>

## 启用前测试

使用单独的用户帐户检查试用、当前已付费、下一期已付费、已过期和不可用结帐状态。所有者和团队成员绕过了大门，因此仅亲自进行测试会错过它。

告诉用户订阅包含哪些内容并显示相关的结束日期。避免将其描述为自动付款或承诺计费 UI 不提供的退款操作。
