<a id="your-analytics-page"></a>

## 您的分析页面

以应用程序所有者或团队成员身份登录时，打开 **我的应用程序 → 您的应用程序 → 编辑 → 分析** 。早期的 `/app/<slug>/analytics` 路由重定向到编辑控制台的分析部分。它显示一个时间窗口（默认为 90 天）的聚合使用情况：

| 公制 | 这算什么 |
| --- | --- |
| **用户** | 在您的应用中记录数据的不同玩家 |
| **会话** | 通过 `saveScore`为提交评分，而不是独立计算游戏场次 |
| **活动** | 窗口中所有存储的 `app-metrics` 行，包括事件记录和得分行 |
| **平均分数** | 保存的平均分 `saveScore` |

使用图表显示窗口上的趋势。

<a id="privacy-built-in"></a>

## 内置隐私

分析是聚合和匿名的：

- 没有显示任何个人用户或原始有效负载。
- 结果被抑制在五个不同的用户以下，因此非常新的应用程序一开始可能不会显示任何数据。
- 总计和趋势是根据最多 20,000 个最近行计算的；不同用户计数是单独计算的。将非常大的总量视为潜在的部分。

<a id="make-your-analytics-useful"></a>

## 让您的分析变得有用

分析是根据您的应用通过 [`app-metrics`](/cn/apps/platform/metrics-and-scores)记录的内容构建的。要获得有意义的数字：

- **记录有意义的事件**，例如 `session_complete` 或 `level_complete`，而不是每一帧。
- 当会话产生结果时，**使用 `saveScore` 保存分数** 。这会驱动 **平均分数** 和当前 **会话** 计数。在一次游戏会话中多次提交分数会增加多次计数。
- **在各个版本中保持事件类型稳定** ，以便趋势保持可比性。

<a id="what-to-watch"></a>

## 看什么

| 信号 | 这可能意味着什么 |
| --- | --- |
| 用户数上升，每个用户的会话数持平 | 新玩家到来但没有回来。查看入职和保存的进度。 |
| 会话数上升，平均分数上升 | 球员们的状态越来越好。考虑更难的内容。 |
| 释放后掉落 | 在播放窗口中检查新版本并阅读最近的评论。 |

您的应用程序页面还显示播放、保存、投票、评论和评论。

<a id="compare-usage-with-sales"></a>

## 比较使用情况与销量

打开 **编辑→商务** 了解产品销售、订阅付款和最近的交易。使用 **编辑→分析** 了解用法。这些面板回答了不同的问题：付费访问并不能保证有人玩过，试用访问并不意味着直接应用程序付款。

使用情况分析仍然是聚合的，并遵守最小队列规则。商业交易记录是一个单独的操作视图，可能会显示缩短的买家钱包地址。

产品收入估算使用当前目录价格；订阅收入使用记录的付款金额。钱包净余额也不是。请参阅 [收入和支出](/cn/apps/operate/revenue-and-payouts) 了解解释和资金获取。
