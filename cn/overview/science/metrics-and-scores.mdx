该区域有两种不同的事物，具有不同的状态：

| | 它是什么 | 状态 |
| --- | --- | --- |
| **SDK 标题分数** |  `biosignal-analytics` 中的开源分数公式，构建者可以在自己的数据上运行 | 实验性（仅来源，不在 npm） |
| ** Elata** | 每个用户一个跨应用分数，根据衍生结果应用程序报告在征得同意的情况下构建 | 实时 |

<a id="from-signals-to-features"></a>

## 从信号到特征

在任何分数之前， SDK 计算 **特征**：定义明确，可重现
数字。

- **EEG 窗口特征：** 频带功率（绝对、相对、对数）、谱熵、主频率、α 峰值、Hjorth 参数和质量标志
- **脉搏特征：** 心率、RMSSD、SDNN 和信号质量
- **稳健的统计：** 中位数和中位数绝对偏差而不是平均值，因此一个坏样本不会扭曲结果
- **个人基线：** 每个人的 30 天滚动中位数和范围，排除异常值

<a id="sdk-headline-scores"></a>

## SDK 标题分数

<Warning>
实验性的。 `biosignal-analytics` 可作为源代码使用，并且可以
  在第一个 npm 发布之前进行更改。
</Warning>

| 分数 | 描述 |
| --- | --- |
| **测量质量** | 记录，而不是人。始终与任何其他乐谱一起使用。 |
| **激活** | 生理唤醒距离人的基线有多远 |
| **恢复** | 激活后唤醒程度恢复情况 |
| **专注度** | 任务期间的参与度 |
| **准备状态** | 对照个人基线的日常状态 |
| **恢复力** | 随着时间的推移，某人恢复的一致性 |

这些是 **产品解释，而不是测量**，并且 SDK 说
所以。两条设计规则使它们保持诚实：

1. **每个贡献者都是可见的。** 每个分数都会公开其输入及其权重、标准化值和质量。
2. **分数自行保留。** 当无法负责任地计算时，分数不会返回任何值以及原因，而不是猜测：

| 原因 | 含义 |
| --- | --- |
| 输入缺失 | 未进行测量 |
| 质量不够 | 做的太差了 |
| 基线不足 | 没有可用的个人基线可与 |进行比较
| 无任务上下文 | 焦点：没有任何事情被关注 |
| 历史记录不足 | 准备时间需要14天；恢复力需要 21 天加上 6 次恢复激活 |

缺失的输入永远不会默默地变成中性的中间值。

<a id="the-biometric-score-on-elata"></a>

##  Elata的生物识别分数

分数是 0 到 100 之间的单个数字，反映用户的结果
在他们使用的所有应用程序中，仅当他们选择**时，才会使用 **。

它是如何构建的：

- **应用程序报告派生的会话结果，而不是原始信号。** 例如，一份报告称，在五分钟的会话中，用户的平静水平从基线的 0.42 上升到了 0.61，信号质量和置信度都很高。
- **相对于用户自身基线的改进很重要**，而不是人与人之间存在差异的绝对值。
- **低质量会话被丢弃**，分数显示为“正在校准”，直到有足够的优质会话稳定为止。
- **对于每个报告，都会在服务器** 上检查同意情况，因此应用程序在没有它的情况下无法做出贡献。
- **只有经过批准的应用程序才能贡献。** 应用程序需要获得 Elata 授予的权限才能计算报告。

请参阅 [隐私和同意](/cn/overview/privacy-and-consent) ，对于构建者，请参阅
[同意和见解](/cn/apps/platform/consent-and-insights)。
