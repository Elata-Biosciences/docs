Elata 让构建者可以通过平台的结帐销售一次性物品和每月应用程序访问权限。用户在 **设置→计费**管理付款；构建者在 **编辑 → 商务**中管理其应用程序的货币化。

<Info>
可用性取决于部署和支付配置。请参阅 [直播内容](/cn/overview/status)。启用后，此处描述的应用程序购买和订阅流程将在 Base 上的 USDC 中结算。预览可以使用真实资金；检查结账时显示的网络。
</Info>

<a id="what-users-can-pay-for"></a>

## 用户可以支付什么

| 购买 | 提供什么 | 在哪里管理 |
| --- | --- | --- |
| 应用内商品 | 一个应用内的一次性解锁 | 设置 → 计费 → 购买 |
| 应用程序订阅 | 在付费期内访问一款订阅门控应用程序 | 设置 → 计费 → 订阅 |
| 积分 | 访问支持的计量功能 | 设置 → 计费 → 钱包 |

应用程序订阅需手动续订。选择下个月的应用程序并不需要付费：完成结帐以确保访问安全。

积分和 [Elata 积分](/cn/overview/points) 与用于购买商品和应用程序订阅的 USDC 是分开的。应用程序订阅访问权限并不授予每个应用程序内项目的所有权。

请参阅 [计费和购买](/cn/users/billing-and-purchases) 了解结帐、访问和计费说明。

<a id="how-builders-earn"></a>

## 建设者如何赚钱

构建者在其应用程序的 **商务** 部分创建产品和订阅计划。一次性物品使用 [`app-payments`](/cn/apps/platform/in-app-purchases)；整个应用程序订阅不需要应用程序内的购买代码。

对于直接应用销售，结帐路线 USDC 通过付款拆分器。分配器扣除配置的平台费用，并将创建者的份额发送到应用程序的支付钱包。没有单独的 Elata 创建者余额可供稍后提取。

 **收入** 报告显示拆分前的总销售额。 **资金** 卡显示支付钱包当前 USDC 余额在 Base。这些是不同的数字：钱包转账、费用和其他钱包活动都会影响余额。

从 [通过您的应用获利](/cn/apps/build/monetize)开始，然后按照 [收入和支出](/cn/apps/operate/revenue-and-payouts) 访问和转移您的资金。

<a id="fees"></a>

## 费用

| 费用 | 适用时 |
| --- | --- |
| 注册费 | 每个应用程序注册时一次；向导显示金额 |
| 平台费用 | 由分流器从应用直接付款中扣除 |
| 网络或支付提供商费用 | 适用于结账或转账 |

<a id="app-tokens"></a>

## 应用代币

购买应用程序项目或订阅访问不需要 ELTA 或应用程序令牌。早期的应用程序令牌启动模型是 [目前已从当前产品中退出](/cn/overview/status#retired-from-the-current-product)。协议功能预计稍后返回，但没有承诺的时间或最终设计。
