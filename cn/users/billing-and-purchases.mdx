有些应用程序提供一次性项目或按月付费访问。 Elata 负责处理结帐并在您的帐户中保存您的购买和访问记录。

<Info>
在配置部署之前，付费功能可能不可用。检查 [实时内容](/cn/overview/status) 以及结账时显示的网络。在此流程中，应用程序项目和应用程序订阅在 Base 上使用 USDC ；另一个网络上的测试网资金无法支付它们。
</Info>

<a id="find-your-billing-settings"></a>

## 找到您的结算设置

打开 [设置→计费](https://app.elata.bio/settings/billing)。

| 部分 | 你能做什么 |
| --- | --- |
| [购买](https://app.elata.bio/settings/billing/purchases) | 查看您拥有的应用程序项目并返回到他们的应用程序 |
| [订阅](https://app.elata.bio/settings/billing/subscriptions) | 查看应用程序访问权限并选择支付期限 |
| [历史](https://app.elata.bio/settings/billing/history) | 查看记录的产品、订阅和信用付款 |
| [钱包](https://app.elata.bio/settings/billing/wallet) | 检查您的账户钱包、连接的钱包和信用余额 |

<a id="buy-an-in-app-item"></a>

## 购买应用内商品

<Steps>
  <Step title="登录并选择商品">
打开应用程序的可用购买或其自己的商店。检查商品描述和价格。一次性物品是购买帐户上永久解锁的物品，而不是每次使用的消耗品。
  </Step>
  <Step title="完成 Elata 结账">
连接或打开结账时要求的钱包。应用程序项目是从 Base 上有足够 USDC 的钱包支付的。确认请求的付款操作并等待结算和记录。
  </Step>
  <Step title="使用您购买的产品">
Elata 确认成功后，应用程序将应用解锁。您可以在 **账单→购买** 下再次找到它，并通过返回同一帐户的应用程序来恢复它。
  </Step>
</Steps>

已拥有的物品应显示已拥有的状态，而不需要再次付款。如果福利缺失，请在购买帐户上重新打开应用程序并检查“购买”，然后再次尝试结账。

<a id="subscribe-to-an-app"></a>

## 订阅应用程序

具有有效月度计划的应用程序会在其应用程序页面或锁定的播放屏幕上显示其价格和任何可用的试用版。符合条件的免费试用无需付款即可开始；付费访问在 **计费 → 订阅**中进行管理。

1. 使用应用程序的订阅提示进行内联结账（如果可用），或打开 **订阅** 来管理您的购物车。
2. 选择提供的期间：当月访问、下个月访问或两者（如果可用）。
3. 查看购物车中的承保日期和总数。多个应用程序可以一起付费。
4. 完成结帐并等待期限显示为已付款。

应用程序订阅期遵循 UTC **日历月**，而不是购买后 30 天。下个月的访问从该月的第一天开始。当提供当月访问权限时，购物车会显示其覆盖范围和按比例分配的价格。

<a id="renew-or-stop-renewing"></a>

### 续订或停止续订

应用程序订阅有 **没有自动付款** 。选择下个月的应用程序会将其添加到您的购物车；仍然需要付款。

要停止续订，请保留下个月的未付款状态。取消选中未付费的选项会将其从购物车中删除。它不会取消或退款您已购买的月份。访问权限在付费承保或试用结束日期内持续有效，然后将过期，除非适用其他形式的访问权限。

<a id="google-sign-in-wallets-and-credits"></a>

## Google 登录、钱包和积分

登录可识别您的 Elata 帐户。完成付款需要有一个能够批准的活跃钱包。 Google 或电子邮件登录可以使用嵌入式钱包。当前结帐尝试自动恢复该钱包，因此您无需携带外部加密钱包即可登录或开始结帐。您可能仍需要在 Base 上添加 USDC 。如果账户钱包无法恢复，请按照恢复或连接提示操作；付款确认发生在钱包的界面中。

**账单 → 钱包** 显示您的帐户钱包和当前连接的钱包。如果不同，请在付款前检查账户和钱包。仅钱包连接并不能保证您的帐户可以验证不同的付款人。

积分涵盖支持的计量功能。充值积分不会为您钱包的 USDC 余额提供资金，也不会自动支付项目或应用程序订阅费用。 [积分](/cn/overview/points) 也是一个单独的参与系统。

<a id="payment-problems-and-history"></a>

## 付款问题和历史记录

| 状态 | 该怎么办 |
| --- | --- |
| 未登录 | 登录到应拥有购买的帐户 |
| 账户钱包恢复 | 等待嵌入式钱包恢复；如果失败则进行恢复 |
| 没有可用的支付钱包 | 按照结账时的钱包连接提示操作 |
| 资金不足 | 将 Base 上的 USDC 添加到支付钱包，然后重试 |
| 等待确认或录音 | 结账结束时保持结账状态 |
| 已付款但无法访问 | 保存交易哈希，检查历史记录和您的访问权限，并在发送另一笔付款之前联系支持人员 |
| 无法结账 | 部署可能未配置付款；返回查看或联系支持人员 |

历史记录是付款记录，而不是退款或发票门户。标记为 **≈** 的产品金额是使用该商品的当前价格估算的；使用交易记录作为实际支付的金额。有限的历史记录可能仅显示最近的记录。

对于计费问题，请使用 [帮助](/cn/users/help) 并包含应用程序、项目或期间、购买帐户、交易哈希（如果可用）以及显示的错误。不要分享钱包秘密。这些设置不提供自助退款工作流程。
