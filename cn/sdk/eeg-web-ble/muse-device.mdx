## MuseBleDevice

`MuseBleDevice` 是底层的 Web Bluetooth 类，负责设备配对、GATT 特征值订阅和数据包解码。`BleTransport` 对它进行封装，以提供规范化的 `HeadbandTransport` 接口。

通常你不需要直接使用 `MuseBleDevice`，请改用 `BleTransport`。

---

## 支持的协议

| 协议 | 头带 | EEG 通道 | 额外数据 |
|----------|-----------|-------------|------------|
| **Classic** | Muse 2、Muse S（经典版） | 4（TP9、AF7、AF8、TP10） | PPG（3 个通道） |
| **Athena** | Muse S（Athena 固件） | 8（TP9、AF7、AF8、TP10、AUX1-4） | 光学、加速度计/陀螺仪、电量 |

连接时会根据设备特征值自动识别协议。

---

## Classic 协议

经典版 Muse 头带以 256 Hz 提供 4 路 EEG 通道。每个通道都有自己的 GATT 特征值：

| 特征值 | 通道 |
|---------------|---------|
| `273e0003-...` | TP9 |
| `273e0004-...` | AF7 |
| `273e0005-...` | AF8 |
| `273e0006-...` | TP10 |

PPG 位于另外 3 个特征值上（`PPG1`、`PPG2`、`PPG3`）。

---

## Athena 协议

Athena 头带使用不同的数据包格式，主要有两个特征值：

| 特征值 | 数据 |
|---------------|------|
| `273e0013-...` | EEG（8 通道，复用） |
| `273e0014-...` | 辅助数据（光学、加速度计/陀螺仪、电量） |

Athena 需要解码器工厂。没有它，连接将失败：

```typescript
import { AthenaWasmDecoder } from "@elata-biosciences/eeg-web";

const transport = new BleTransport({
  deviceOptions: {
    athenaDecoderFactory: () => new AthenaWasmDecoder(),
  },
});
```

## MuseBoardInfo

连接后由 `getBoardInfo()` 返回：

```typescript
interface MuseBoardInfo {
  device_name: string;
  sample_rate_hz: number;        // 256
  channel_count: number;         // 4 或 8
  eeg_channel_names: string[];
  board_id: number;
  protocol: "classic" | "athena";
  optics_channel_count: number;
  description: string;
}
```

## 浏览器兼容性

| 浏览器 | 平台 | 状态 |
|---------|----------|--------|
| Chrome 56+ | Windows、macOS、Linux、Android | 支持 |
| Edge 79+ | Windows、macOS | 支持 |
| Opera 43+ | 桌面 | 支持 |
| Safari | macOS、iOS | 不支持 |
| Firefox | 所有平台 | 不支持 |

<Warning>
  Web Bluetooth 需要 HTTPS。它无法在 `http://` 上工作（开发时的 `localhost` 除外）。
</Warning>

---

## Safari/iOS 替代方案

支持 iOS 的三种策略：

1. **原生应用外壳**（推荐）：用 Swift 和 CoreBluetooth 实现 BLE，将帧桥接到 Web 界面
2. **配套桥接**：原生应用通过 WebSocket/WebRTC 将帧传给 Web 应用
3. **混合 WebView**：使用带原生消息处理器的 `WKWebView` 处理 BLE

无论哪种方式，都应以 `HeadbandFrameV1` 结构作为接口边界，让浏览器和原生传输输出相同的帧结构。
