## What this guide covers

This guide shows how to:

- capture webcam frames in the browser
- detect a face and extract a face region
- feed samples into the rPPG processor
- read live BPM and signal quality
- improve estimates with Muse PPG when available

## Before you start

You need:

- `@elata-biosciences/rppg-web`
- a browser with camera access (`getUserMedia`) and WebAssembly support
- `https://` or `localhost`

<CodeGroup>

```bash npm
npm install @elata-biosciences/rppg-web
```

```bash pnpm
pnpm add @elata-biosciences/rppg-web
```

</CodeGroup>

<Info>
rPPG works best when the face is well lit, mostly still, and fully visible in frame.
</Info>

<Tip>
Most apps should use `createRppgSession()`, which wraps everything on this page (WASM init, frame capture, ROI selection, diagnostics, cleanup). See [rPPG in a browser app](/sdk/guides/rppg-browser). Use the lower-level pieces below only when you need custom orchestration.
</Tip>

## Quick integration with DemoRunner

`DemoRunner` handles frame capture, face detection, ROI extraction, and processing in one flow, while leaving you in control of the processor.

```ts
import {
  RppgProcessor,
  MediaPipeFrameSource,
  DemoRunner,
  loadWasmBackend,
} from "@elata-biosciences/rppg-web";

const video = document.querySelector("video")!; // a playing camera <video>
const backend = await loadWasmBackend(); // null if the packaged WASM can't be loaded
if (!backend) throw new Error("rPPG WASM backend unavailable");
const source = new MediaPipeFrameSource(video);
const processor = new RppgProcessor(backend, 30);

const runner = new DemoRunner(source, processor, {
  useSkinMask: true,
  onStats: () => {
    const metrics = processor.getMetrics();

    document.getElementById("bpm")!.textContent =
      metrics.bpm?.toFixed(0) ?? "--";

    document.getElementById("quality")!.textContent =
      `${(metrics.confidence * 100).toFixed(0)}%`;
  },
});

await runner.start();
```

<Tip>
Show BPM only when `metrics.confidence` is above your app's threshold. A threshold around `0.5` is a practical starting point.
</Tip>

## Manual pipeline

Use the manual path when you want tighter control over face tracking, sampling, or how your app renders intermediate results.

<Steps>
  <Step title="Load the face model and create a frame source">

  ```ts
  import {
    MediaPipeFaceFrameSource,
    loadFaceLandmarker,
  } from "@elata-biosciences/rppg-web";

  // Loads MediaPipe FaceLandmarker from a CDN; returns null if unavailable.
  const faceLandmarker = await loadFaceLandmarker();
  if (!faceLandmarker) throw new Error("Face tracking unavailable");
  const source = new MediaPipeFaceFrameSource(video, faceLandmarker);
  ```

  </Step>

  <Step title="Create the processor">

  ```ts
  import { RppgProcessor, loadWasmBackend } from "@elata-biosciences/rppg-web";

  const backend = await loadWasmBackend();
  if (!backend) throw new Error("rPPG WASM backend unavailable");
  const processor = new RppgProcessor(backend, 30, 10);
  ```

  The third argument sets a 10-second analysis window.

  </Step>

  <Step title="Push samples from the face ROI">

  ```ts
  import { averageGreenInROI } from "@elata-biosciences/rppg-web";

  source.onFrame = (frame) => {
    if (!frame.roi) return;

    const { x, y, w, h } = frame.roi;
    const green = averageGreenInROI(frame, x, y, w, h);

    processor.pushSample(
      frame.timestampMs ?? performance.now(),
      green,
    );
  };
  ```

  </Step>

  <Step title="Start the camera and read metrics">

  ```ts
  await source.start();

  setInterval(() => {
    const metrics = processor.getMetrics();
    console.log("BPM:", metrics.bpm, "confidence:", metrics.confidence);
  }, 1000);
  ```

  </Step>
</Steps>

## Add Muse calibration

If a Muse device is available, you can use its PPG as a reference signal to improve camera-based estimates.

```ts
// `processor` is the RppgProcessor created above
processor.updateMuseMetrics(museBpm, 0.9, performance.now());
```

<Info>
For a fuller fusion workflow, including `MuseFusionCalibrator` and calibration models, continue to [/sdk/rppg-web/calibration](/sdk/rppg-web/calibration).
</Info>

## Quality checklist

Use this checklist before debugging the pipeline:

- keep lighting even across the face
- reduce head movement
- wait 5 to 10 seconds before trusting early BPM output
- make sure a face ROI is actually being detected
- enable `useSkinMask` when you use `DemoRunner`
