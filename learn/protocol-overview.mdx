## Overview

Elata is a platform for building and distributing apps that use the body's
signals: heart rate from a webcam, brain activity from a consumer EEG headband,
and more.

It brings together three things:

1. **Biometric SDKs**: npm packages that capture and process biosignals in the browser, across devices.
2. **On-device processing**: raw signals stay on the user's device.
3. **The Elata App Store**: where builders publish these apps and users find and play them, with sign-in, payments, and storage built in.

## Why this exists

Consumer devices have quietly become biosignal sensors. A smartphone or laptop
camera can estimate heart rate and breathing. Consumer EEG headsets capture
brain activity that needed clinical hardware a decade ago.

The sensors are already in people's pockets. What's missing is a standard
application layer on top of them. Today, companies that process biosignals
usually send users' data to their own servers, and every builder recreates the
same signal-processing pipeline from scratch.

Elata addresses this with:

1. **Published SDKs** that standardize biosignal capture across devices.
2. **On-device processing**, so raw data never has to leave the user's device.
3. **A store with the plumbing built in**, so a builder can ship a biosignal app without building auth, payments, hosting, or storage.

## What Elata provides

### Biometric SDKs

| Package | What it does |
| --- | --- |
| `@elata-biosciences/rppg-web` | Heart rate and pulse signals from a standard webcam (rPPG). No wearable needed. |
| `@elata-biosciences/eeg-web` | EEG signal processing and models in the browser (WebAssembly). |
| `@elata-biosciences/eeg-web-ble` | Connect consumer EEG headsets over Web Bluetooth. Muse built in. |
| `@elata-biosciences/ppg-web` | Heart rate and HRV from a headband's optical (PPG) sensor. |
| `@elata-biosciences/biosignal-session` | Record multi-sensor sessions locally. |
| `@elata-biosciences/biosignal-analytics` | Features, HRV, and headline scores from recorded signals. |

See the full list in the [SDK overview](/sdk/overview).

### Privacy by design

Signal processing runs in the browser. Raw camera frames and raw biosignals
never need to leave the device. Users can choose to share **derived** session
results to build a cross-app Score, and they can turn that off at any time. See
[Privacy and data](/learn/privacy-and-data).

### The App Store

Builders upload a web build. The store scans and reviews it, hosts it in a
secure sandbox, and gives it sign-in, in-app purchases, subscriptions, and
per-user storage through a small set of [platform APIs](/apps/platform/host-bridge).
