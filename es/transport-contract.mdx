Este es el contrato que debe cumplir su integración.

Las aplicaciones deberían ver una superficie de transporte estable Elata , no un paquete específico del proveedor
formatos o detalles de Bluetooth.

<a id="the-core-rule"></a>

## La regla básica

El adaptador de su dispositivo debe emitir `HeadbandFrameV1` fotogramas a través de un
`HeadbandTransport`.

Ese es el límite de compatibilidad para las aplicaciones del navegador y el análisis posterior.

<Info>
Si el contrato marco es correcto, el código de la aplicación puede seguir siendo simple. si el marco
  El contrato es inestable, todo lo que está encima se vuelve más difícil de confiar.
</Info>

## `HeadbandFrameV1`

Cada transporte produce la misma forma de marco de nivel superior:

```ts
interface HeadbandFrameV1 {
  schemaVersion: "v1";
  source: string;
  sequenceId: number;
  emittedAtMs: number;
  eeg: HeadbandSignalBlock;
  ppgRaw?: HeadbandSignalBlock;
  optics?: HeadbandSignalBlock;
  accgyro?: HeadbandSignalBlock;
  battery?: HeadbandBatteryBlock;
}
```

En la práctica, la mayoría de las integraciones deberían tratar `eeg` como el bloque requerido y agregar
otros bloques sólo cuando el dispositivo los exponga claramente.

## `HeadbandSignalBlock`

La carga útil EEG debe normalizarse en esta forma:

```ts
interface HeadbandSignalBlock {
  sampleRateHz: number;
  channelNames: string[];
  channelCount: number;
  samples: number[][];
  timestampsMs?: number[];
  clockSource?: "device" | "local";
}
```

<a id="what-must-stay-stable"></a>

## Lo que debe permanecer estable

| Campo | Qué bien se ve |
| --- | --- |
| `source` | Un identificador estable y legible como `vendor-ble` |
| `sequenceId` | Monótono dentro de la sesión de carrera |
| `sampleRateHz` | Coincide con el comportamiento real del dispositivo |
| `channelNames` | Estable y documentado |
| `channelCount` | Siempre coincide con el ancho de fila real |
| `samples` | Cada fila es un paso de tiempo y utiliza el mismo orden de canales |
| `timestampsMs` | Opcional, pero alineado con las filas emitidas cuando están presentes |
| `clockSource` | Documentado explícitamente como `device` o `local` |

## `HeadbandTransport`

Todos los transportes implementan la misma superficie de ciclo de vida:

```ts
interface HeadbandTransport {
  onFrame?: (frame: HeadbandFrameV1) => void;
  onStatus?: (status: HeadbandTransportStatus) => void;
  connect(): Promise<void>;
  disconnect(): Promise<void>;
  start(): Promise<void>;
  stop(): Promise<void>;
}
```

<a id="lifecycle-expectations"></a>

## Expectativas del ciclo de vida

| Método | Comportamiento esperado |
| --- | --- |
| `connect()` | Empareja o conecta al dispositivo y prepara la sesión |
| `start()` | Comenzar a transmitir fotogramas válidos |
| `stop()` | Detener la transmisión sin corromper la sesión |
| `disconnect()` | Liberar la sesión y los recursos subyacentes |

Las reglas de transición importan tanto como los métodos mismos. un limpio
La integración debería hacer evidente si el transporte está inactivo, conectado,
streaming, degradado, reconectándose, desconectado o con error.

## `HeadbandTransportStatus`

Las actualizaciones de estado deben ser lo suficientemente explícitas para que las aplicaciones reaccionen correctamente:

```ts
interface HeadbandTransportStatus {
  state: HeadbandTransportState;
  atMs: number;
  reason?: string;
  errorCode?: string;
  recoverable?: boolean;
  details?: Record<string, unknown>;
}
```

<a id="practical-rules-for-integrators"></a>

## Reglas Prácticas para Integradores

<Steps>
  <Step title="Mantener el orden de los canales fijo">
Si el dispositivo transmite `TP9, AF7, AF8, TP10`, cada fila emitida debe usar
    ese orden consistentemente.
  </Step>
  <Step title="Hacer que el ancho de fila coincida con el número de canales">
Una fila nunca debe contener más o menos valores EEG que `channelCount`.
  </Step>
  <Step title="Utilice la frecuencia de muestreo adecuada">
No codifique un valor nominal si la tasa de salida real difiere.
  </Step>
  <Step title="Comportamiento de la marca de tiempo del documento">
Indique si las marcas de tiempo provienen del reloj del dispositivo o del reloj del navegador local.
  </Step>
  <Step title="Fallos superficiales a través de actualizaciones de estado.">
Las aplicaciones necesitan señales claras de desconexiones, reintentos y errores irrecuperables.
  </Step>
</Steps>

<a id="minimal-usage-pattern"></a>

## Patrón de uso mínimo

```ts
const transport: HeadbandTransport = /* BleTransport or another transport */;

transport.onFrame = (frame) => {
  const eegRows = frame.eeg.samples;
  console.log(eegRows.length);
};

transport.onStatus = (status) => {
  console.log(status.state, status.reason ?? "");
};

await transport.connect();
await transport.start();

// ... later
await transport.stop();
await transport.disconnect();
```
