La confiabilidad es el objetivo principal de esta página.

La integración de un dispositivo debería sobrevivir a las condiciones del mundo real, no solo a una demostración limpia
sesión.

<a id="definition-of-done"></a>

## Definición de Hecho

La integración estará lista cuando se cumpla todo lo siguiente:

| Verificar | Qué verificar |
| --- | --- |
| Ancho del marco | El ancho de cada fila coincide con `numEegChannels` |
| Orden del canal | La orden es estable y documentada |
| Frecuencia de muestreo | Coincide con la salida real del dispositivo |
| Transiciones de estado | Conectar, iniciar, detener, desconectar y las fallas aparecen claramente |
| Manejo de paquetes | Los paquetes cortos o con formato incorrecto se rechazan de forma segura |
| Comportamiento de reconexión | La sesión puede recuperarse o fallar claramente |

<a id="minimum-test-set"></a>

## Conjunto mínimo de prueba

<Steps>
  <Step title="feliz camino">
Verifique `connect -> start -> frames -> stop -> disconnect` con BLE simulado o
    accesorios del puente.
  </Step>
  <Step title="Manejo de paquetes mal formados">
Introduzca paquetes cortos, corruptos o parciales en el decodificador y confirme que
    se rechazan de forma segura.
  </Step>
  <Step title="Comportamiento de desconectar y reconectar">
Simule la pérdida del dispositivo, las desconexiones del navegador y el comportamiento de reintento.
  </Step>
  <Step title="Variantes de firmware">
Agregue dispositivos para diferencias de protocolo conocidas en las líneas de firmware compatibles.
  </Step>
  <Step title="Verificación de metadatos">
Confirme los nombres de los canales, el recuento, la frecuencia de muestreo y el manejo de la marca de tiempo.
  </Step>
</Steps>

<a id="what-to-test-first"></a>

## Qué probar primero

| Área | Por qué suele fallar primero |
| --- | --- |
| Filtros de descubrimiento | Los filtros incorrectos ocultan el dispositivo o exponen dispositivos no relacionados |
| Configuración de características | Un UUID incorrecto o falta notificación de bloques de pasos de transmisión |
| Suposiciones del decodificador | Errores de endianidad, tamaño de paquete o escalado filas corruptas |
| Desmontaje de sesión | Las suscripciones huérfanas hacen que las reconexiones sean inestables |
| Lógica de marca de tiempo | Aún pueden llegar muestras atractivas con metadatos de sincronización incorrecta |

<a id="ci-guidance"></a>

## Guía de CI

No se requiere hardware real para CI.

Utilice Bluetooth simulado o puente de E/S y accesorios de paquetes estables para que las pruebas sean
repetible y fácil de mantener.

<Check>
Un buen conjunto de accesorios es más valioso que una prueba manual en un vehículo real.
  auricular.
</Check>

<a id="manual-validation-pass"></a>

## Pase de Validación Manual

Después de que las pruebas automatizadas estén en verde, realice una prueba de dispositivo real para cada dispositivo compatible.
línea de firmware.

| Comprobación manual | Qué confirmar |
| --- | --- |
| Emparejamiento inicial | el navegador puede detectar y conectarse limpiamente |
| Inicio de transmisión | Los fotogramas comienzan sin suscripciones duplicadas |
| Duración de la sesión | la transmisión se mantiene estable con el tiempo |
| Interrupciones | las desconexiones transitorias se comportan de manera predecible |
| Recuperación | el dispositivo se puede detener y reiniciar |

<a id="common-failure-patterns"></a>

## Patrones de fallas comunes

<AccordionGroup>
  <Accordion title="Los marcos parecen válidos pero las funciones posteriores son incorrectas">
Verifique el orden de los canales, la escala y la frecuencia de muestreo antes de mirar los modelos.
  </Accordion>
  <Accordion title="La primera transmisión funciona pero falla la reconexión.">
Revisar el desmontaje. La mayoría de los errores de reconexión provienen de suscripciones obsoletas o de un
    liberación de sesión incompleta.
  </Accordion>
  <Accordion title="La transmisión comienza pero el tiempo no es consistente">
Revise el comportamiento de las marcas de tiempo y el procesamiento por lotes de paquetes. Los valores de muestra pueden verse bien
    mientras que los metadatos de sincronización siguen siendo incorrectos.
  </Accordion>
  <Accordion title="La integración funciona en un solo firmware.">
Separe el manejo de paquetes específicos de la versión y agregue dispositivos para cada uno compatible.
    rama de firmware.
  </Accordion>
</AccordionGroup>

<a id="release-readiness-checklist"></a>

## Lista de verificación de preparación para la liberación

Antes de entregar la integración, asegúrese de poder responder estas preguntas con claridad:

1. qué dispositivos y versiones de firmware se probaron
2. qué navegadores y plataformas se probaron
3. qué limitaciones conocidas aún existen
4. qué comportamiento de recuperación deben esperar las aplicaciones
5. quién posee el mantenimiento futuro
