title: "Implementación del adaptador"
description: "Construya un adaptador de dispositivo que se conecte a BleTransport y emita marcos de diadema estables."
---

Una vez que su inventario de protocolo esté completo, cree el adaptador.

El objetivo es aislar la lógica de paquetes y BLE específica del dispositivo preservando al mismo tiempo la
contrato de transporte compartido Elata para apps.

<a id="recommended-shape"></a>

## Forma recomendada

Para integraciones BLE del navegador, el adaptador debe cumplir con la forma `BleDeviceLike`
esperada por `@elata-biosciences/eeg-web-ble`.

Eso significa que la capa del dispositivo maneja el descubrimiento, la configuración de la sesión, la suscripción y
decodificación de paquetes, mientras que `BleTransport` maneja la superficie de transporte orientada a la aplicación.

<a id="implementation-order"></a>

## Orden de implementación

<Steps>
  <Step title="Implementar descubrimiento">
Defina los filtros `requestDevice` y los servicios opcionales necesarios para encontrar
    el dispositivo limpiamente en el selector del navegador.
  </Step>
  <Step title="preparar la sesión">
Conéctese a GATT, resuelva características y realice cualquier escritura inicial que sea necesaria.
    requerido antes de que pueda comenzar la transmisión.
  </Step>
  <Step title="Decodificar paquetes en EEG filas">
Convierta los paquetes de proveedores en `number[][]` donde cada fila es un paso de tiempo y
    el ancho de la fila coincide con `numEegChannels`.
  </Step>
  <Step title="Emitir metadatos estables">
Exponer `samplingRate`, `eegNames`, `numEegChannels`y el dispositivo relacionado
    metadatos con precisión.
  </Step>
  <Step title="Manejar el tope y soltar limpiamente">
Cancelar la suscripción, detener la transmisión de forma segura y liberar la sesión sin fugas
    recursos.
  </Step>
</Steps>

<a id="minimal-adapter-skeleton"></a>

## Esqueleto adaptador mínimo

```ts
import type { BleDeviceLike } from "@elata-biosciences/eeg-web-ble";

export class VendorBleDevice implements BleDeviceLike {
  isAthena = false;
  samplingRate = 250;
  eegNames = ["CH1", "CH2"];
  numEegChannels = 2;
  opticsChannelCount = 0;

  getBoardInfo() {
    return { device_name: "VENDOR_DEVICE" };
  }

  getCharacteristicInfo() {
    return { characteristics: [] };
  }

  async prepareSession() {
    // Connect to GATT, resolve characteristics, and initialize streaming state
  }

  async releaseSession() {
    // Tear down subscriptions and release the browser session
  }

  async startStream(eegCb, _ppgCb) {
    // Subscribe to notifications and emit decoded EEG rows
    eegCb([[0, 0]]);
  }

  async stopStream() {
    // Stop device streaming and unsubscribe
  }
}
```

<a id="what-the-adapter-must-own"></a>

## Qué debe poseer el adaptador

| Responsabilidad | ¿Es propietario del adaptador? |
| --- | --- |
| Descubrimiento de dispositivos | sí |
| Conexión GATT y configuración de características | sí |
| Decodificación de paquetes | sí |
| Metadatos precisos | sí |
| Ciclo de vida del transporte orientado a la aplicación | generalmente hasta `BleTransport` |
| Entrega de cuadros normalizada a apps | mediante el contrato de transporte compartido |

<a id="packet-decoding-rules"></a>

## Reglas de decodificación de paquetes

Mantenga el decodificador aburrido y determinista.

| Regla | Por qué es importante |
| --- | --- |
| Rechaza anticipadamente paquetes con formato incorrecto | Evita que las filas incorrectas lleguen a las aplicaciones |
| Preserva el orden de los canales | Mantiene las características y modelos posteriores consistentes |
| Filas por lotes solo cuando sea necesario | Evita la latencia oculta y la confusión de marcas de tiempo |
| Realice un seguimiento de los contadores de paquetes cuando estén disponibles | Ayuda a detectar caídas o daños |
| Separa EEG de la lógica auxiliar limpiamente | Facilita la depuración y las pruebas |

<a id="session-lifecycle-rules"></a>

## Reglas del ciclo de vida de la sesión

Su adaptador debería hacer que estas transiciones no sean sorprendentes:

| Etapa | Buen comportamiento |
| --- | --- |
| Descubrir | solo se muestran los dispositivos coincidentes |
| Conectar | los servicios y características requeridos se resuelven claramente |
| Iniciar | la transmisión comienza una vez, sin suscripciones duplicadas |
| Detener | las notificaciones se detienen limpiamente |
| Libere | la sesión se puede iniciar nuevamente más tarde |

<a id="reliability-notes"></a>

## Notas de confiabilidad

<Info>
  `startStreaming()` es el valor predeterminado más seguro para los consumidores de aplicaciones porque combina
  conectarse y comenzar. Su adaptador aún debería hacer que los pasos subyacentes `connect()`
  y `start()` sean confiables por sí solos.
</Info>

Si el dispositivo expone señales auxiliares como PPG, óptica, IMU o batería,
mapearlos sólo cuando la semántica sea clara. No fuerces Muse-específico
suposiciones en hardware que no esMuse .
