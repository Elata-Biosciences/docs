## Nuestra postura

Elata crea herramientas para **bienestar, juegos, aprendizaje e investigación**. el
Las señales Elata que usan las aplicaciones (frecuencia cardíaca de la cámara, consumidor EEGy diadema PPG) son
mediciones fisiológicas reales, pero provienen de dispositivos de consumo en
entornos no controlados. Son estimaciones, no lecturas clínicas.

De esto se siguen tres reglas:

1. **Sin diagnóstico. Las aplicaciones** Elata y Elata no diagnostican, tratan ni monitorean condiciones médicas.
2. **Muestra la incertidumbre.** Las medidas vienen con valores de confianza y calidad de la señal, y las puntuaciones se retienen cuando los datos no son lo suficientemente buenos en lugar de adivinar.
3. **Califique cada reclamo.** Una frecuencia cardíaca medida y una puntuación de "concentración" son diferentes tipos de reclamos, y el SDK los etiqueta de manera diferente.

## Cómo se califican las reclamaciones

El paquete de análisis de SDK(`biosignal-analytics`, actualmente
[experimental](/es/overview/status)) proporciona a cada métrica una definición registrada
con dos etiquetas.

**Clase de medida:** qué tipo de número es.

| Clase | Significado | Ejemplo |
| --- | --- | --- |
| Medido | Leer más o menos directamente de la señal | Frecuencia cardíaca |
| Derivado (determinista) | Calculado a partir de valores medidos mediante una fórmula fija | HRV (RMSSD), potencia de banda |
| Inferido por el modelo | Estimado mediante un modelo estadístico o aprendido | Una reconstrucción de forma de onda aprendida |
| Producto compuesto | Una interpretación del producto que combina varias entradas | Enfoque, preparación |

**Nivel de evidencia:** qué tan fuertemente se respalda la métrica.

| Nivel | Significado |
| --- | --- |
| Beta predeterminada | Bien soportado; mostrado por defecto |
| Avanzado | Compatible, pero para usuarios informados |
| Experimental | Temprano; puede cambiar o eliminarse |
| Rechazado | Evaluado y deliberadamente no utilizado |

Cada valor también registra el algoritmo exacto y la versión que lo produjo, por lo que
se puede rastrear y recalcular cuando mejora un algoritmo. El código de característica es
probado contra implementaciones de referencia (NumPy/SciPy) para que los números concuerden
en las versiones Rust, WebAssemblyy JavaScript .
