title: "Agregue EEG a una aplicación de navegador existente"

Utilice esta página si ya tiene una aplicación de navegador y desea la recomendada
ruta de integración de la aplicación existente EEG .

Si desea la ruta del andamio, utilice [Inicio rápido](/es/sdk/tutorials/first-app). si tu
Primero solo necesita el modelo del paquete, use [EEG en una aplicación de navegador](/es/sdk/guides/eeg-browser).

Este tutorial muestra la ruta recomendada para agregar
`@elata-biosciences/eeg-web` a una aplicación de navegador existente.

EEG es **opcional** en el viaje típico Elata . **Cámara rPPG** es la habitual
integración primaria a menos que su producto necesite funciones de señales cerebrales.

Úselo cuando su aplicación necesite EEG API de análisis en el navegador.
Si también necesita transporte de auriculares en vivo, agregará
`@elata-biosciences/eeg-web-ble` después de este tutorial.

<a id="what-you-will-build"></a>

## Lo que construirás

Usted:

1. instalar `@elata-biosciences/eeg-web`
2. inicializa el tiempo de ejecución EEG WASM 
3. ejecutar una llamada de análisis simple
4. verifique que su aplicación pueda servir los activos WASM empaquetados

<a id="step-1-install-the-package"></a>

## Paso 1: instalar el paquete

<CodeGroup>

```bash pnpm
pnpm add @elata-biosciences/eeg-web
```

```bash npm
npm install @elata-biosciences/eeg-web
```

</CodeGroup>

<a id="step-2-create-a-small-eeg-module"></a>

## Paso 2: Crear un pequeño módulo EEG 

Cree un pequeño módulo en su aplicación para que la integración permanezca aislada y sea fácil de realizar.
prueba (por ejemplo `src/eeg.ts`):

```ts eeg.ts
import { initEegWasm, band_powers } from "@elata-biosciences/eeg-web";

let eegInitPromise: Promise<void> | null = null;

async function ensureEegReady() {
  if (!eegInitPromise) {
    eegInitPromise = initEegWasm();
  }
  await eegInitPromise;
}

export async function analyzeExampleEeg() {
  await ensureEegReady();

  const eegData = new Float32Array([0.2, 0.5, 0.1, -0.3, -0.4, 0.1, 0.2, 0.6]);
  const powers = band_powers(eegData, 256);

  return powers;
}
```

Por qué esta forma:

- `initEegWasm()` debe ejecutarse antes de utilizar los asistentes de análisis
- la Promesa a nivel de módulo evita inicializaciones repetidas, incluidas llamadas simultáneas
- mantenerlo en un archivo hace que sea más fácil intercambiar muestras reales más adelante

<a id="step-3-call-it-from-your-ui"></a>

## Paso 3: Llámelo desde su interfaz de usuario

Por ejemplo, en un componente o archivo de entrada:

```ts
import { analyzeExampleEeg } from "./eeg";

const powers = await analyzeExampleEeg();
console.log("alpha", powers.alpha);
console.log("beta", powers.beta);
```

En esta etapa todavía no estás utilizando unos auriculares reales. Estás demostrando que el
La aplicación del navegador puede cargar el tiempo de ejecución y ejecutar las funciones EEG correctamente.

<a id="step-4-verify-the-wasm-asset-path"></a>

## Paso 4: Verificar la ruta del activo WASM 

Ejecute su aplicación en desarrollo y confirme que el módulo se inicialice sin errores.

Si `initEegWasm()` falla, el problema más probable es que su paquete o aplicación
La implementación no sirve correctamente los activos `wasm/` empaquetados.

Esto es lo primero que hay que solucionar antes de agregar más lógica de producto.

Si está utilizando Vite, las dos soluciones comunes son:

1. agrega `vite-plugin-wasm` y `vite-plugin-top-level-await`, luego sigue usando
   `await initEegWasm()`
2. importe la URL del activo WASM directamente y pásela a `initEegWasm(wasmUrl)`

Consulte [Solución de problemas](/es/sdk/operations/troubleshooting) para obtener más información sobre ambas soluciones.

Si está atascado, compare su aplicación con la aplicación scaffolded `eeg-demo`
antes de asumir que el paquete en sí no funciona.

<a id="step-5-replace-example-data-with-real-app-data"></a>

## Paso 5: Reemplace datos de ejemplo con datos reales de la aplicación

Una vez que la llamada de ejemplo funcione, intercambie la matriz de marcador de posición con la muestra EEG real
buffers de su aplicación.

El patrón común es:

1. recibir o cargar EEG muestras
2. normalizarlos en matrices escritas
3. llamar al Elata ayudantes de análisis
4. asigna el resultado al estado de la aplicación, comentarios, puntuación o visualizaciones

Ese último paso es donde reside el comportamiento de su producto.

<a id="when-to-add-eeg-web-ble"></a>

## Cuándo agregar `eeg-web-ble`

Agregue `@elata-biosciences/eeg-web-ble` cuando necesite transporte de navegador en vivo desde
un auricular compatible con Muse.

No comience allí si el tiempo de ejecución simple EEG aún no funciona. Haga que la carga WASM
funcione primero y luego agregue el transporte.

<a id="common-problems"></a>

## Problemas Comunes

- `initEegWasm()` arroja: su aplicación probablemente no esté cargando los recursos empaquetados `wasm/` correctamente
- Esperaba que se descubriera el dispositivo: `eeg-web` no realiza el transporte Bluetooth por sí solo
- Estás evaluando el SDK desde cero: comienza con [Crea tu primera Elata aplicación](/es/sdk/tutorials/first-app) en lugar de la configuración manual
