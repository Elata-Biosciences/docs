<a id="musebledevice"></a>

## Dispositivo MuseBle

`MuseBleDevice` es la clase Web Bluetooth de bajo nivel que maneja el emparejamiento de dispositivos, las suscripciones a características GATT y la decodificación de paquetes. `BleTransport` lo envuelve para proporcionar la interfaz `HeadbandTransport` normalizada.

Normalmente no utilizas `MuseBleDevice` directamente. Utilice `BleTransport` en su lugar.

---

<a id="supported-protocols"></a>

## Protocolos admitidos

| Protocolo | Diademas | EEG Canales | Datos extra |
|----------|-----------|-------------|------------|
| **Clásico** | Muse 2, Muse S (clásico) | 4 (TP9, AF7, AF8, TP10) | PPG (3 canales) |
| **Athena** | Muse S (Athena firmware) | 8 (TP9, AF7, AF8, TP10, AUX1-4) | Óptica, accgyro, batería |

El protocolo se detecta automáticamente durante la conexión según las características del dispositivo.

---

<a id="classic-protocol"></a>

## Protocolo clásico

Las diademas clásicas Muse exponen 4 EEG canales a 256 Hz. Cada canal tiene su propia característica GATT:

| Característica | Canal |
|---------------|---------|
| `273e0003-...` | TP9 |
| `273e0004-...` | AF7 |
| `273e0005-...` | AF8 |
| `273e0006-...` | TP10 |

PPG está disponible en 3 características adicionales (`PPG1`, `PPG2`, `PPG3`).

---

<a id="athena-protocol"></a>

## Athena Protocolo

Athena Las diademas utilizan un formato de paquete diferente con dos características principales:

| Característica | Datos |
|---------------|------|
| `273e0013-...` | EEG (8 canales, multiplexados) |
| `273e0014-...` | Auxiliar (óptica, accgiro, batería) |

Athena requiere una fábrica de decodificadores. Sin uno, la conexión fallará:

```typescript
import { AthenaWasmDecoder } from "@elata-biosciences/eeg-web";

const transport = new BleTransport({
  deviceOptions: {
    athenaDecoderFactory: () => new AthenaWasmDecoder(),
  },
});
```

<a id="museboardinfo"></a>

## Información del tablero Muse

Devuelto por `getBoardInfo()` después de la conexión:

```typescript
interface MuseBoardInfo {
  device_name: string;
  sample_rate_hz: number;        // 256
  channel_count: number;         // 4 or 8
  eeg_channel_names: string[];
  board_id: number;
  protocol: "classic" | "athena";
  optics_channel_count: number;
  description: string;
}
```

</Warning>

<a id="safariios-workarounds"></a>

## Safari/Soluciones alternativas para iOS

Tres estrategias para la compatibilidad con iOS:

1. **Shell de aplicación nativa** (recomendado): implemente BLE en Swift con CoreBluetooth, conecte marcos a la interfaz de usuario web
2. **Puente complementario**: la aplicación nativa transmite fotogramas a través de WebSocket/WebRTC a la aplicación web
3. **WebView híbrido**: `WKWebView` con controladores de mensajes nativos para BLE

En todos los casos, utilice el esquema `HeadbandFrameV1` como límite de la interfaz para que el navegador y los transportes nativos emitan la misma forma de marco.
