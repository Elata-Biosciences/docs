tutorial completo.

[Stream Muse-Compatible EEG Over Web Bluetooth](/es/sdk/tutorials/eeg-ble-live-stream).
Si desea la ruta de andamio, use [Cree su primera Elata aplicación](/es/sdk/tutorials/first-app).

<Info>
  **Función en la SDK:** cámara **rPPG** es la primera aplicación habitual. **EEG** es opcional cuando necesitas señales cerebrales. **Web Bluetooth** (`eeg-web-ble` con `eeg-web`) habilita un auricular compatible con Museen vivo. Es transporte para EEG, no un producto primario paralelo a rPPG.
</Info>

<a id="start-with-a-known-good-scaffolded-app"></a>

## Comience con una aplicación con andamios conocida y buena

Si desea la ruta más rápida a un ejemplo BLE de navegador que funcione, primero cree la aplicación de inicio EEG
:

<CodeGroup>

```bash pnpm
pnpm create @elata-biosciences/elata-demo my-app -- --template eeg-ble
cd my-app
pnpm install
pnpm run dev
```

```bash npm
npm create @elata-biosciences/elata-demo my-app -- --template eeg-ble
cd my-app
npm install
npm run dev
```

</CodeGroup>

Utilice el resto de esta guía cuando desee agregar el mismo flujo BLE del navegador a una aplicación existente.

---

<a id="requirements"></a>

## Requisitos

- Chrome, Edgeo Bluefy en iOS
- `https://` o `localhost`
- Bluetooth habilitado en la máquina
- Un dispositivo Musecompatible con EEG 

Clases de dispositivos compatibles:

- Muse 2 y Muse S dispositivos BLE clásicos
- Muse S Athena dispositivos con protocolo v2
- El puente BLE sintético compatible con Museutilizado para las pruebas

<Note>
Para el navegador BLE, utilice Chrome en escritorio o Android, o Bluefy en iOS. No espere que Safari maneje este flujo de trabajo por sí solo.
</Note>

<a id="minimal-integration"></a>

## Integración mínima

```ts
import { AthenaWasmDecoder } from "@elata-biosciences/eeg-web";
import { BleTransport } from "@elata-biosciences/eeg-web-ble";

const transport = new BleTransport({
  deviceOptions: {
    athenaDecoderFactory: () => new AthenaWasmDecoder(),
  },
});

transport.onFrame = (frame) => {
  console.log(frame.eeg.samples.length);
};

transport.onStatus = (status) => {
  console.log(status.state, status.reason);
};

await transport.connect();
await transport.start();
```

---

<a id="typical-flow"></a>

## Flujo típico

1. Confirme que la aplicación se esté ejecutando en un contexto seguro.
2. Construir `BleTransport`.
3. Proporcione `athenaDecoderFactory` si necesita soporte Athena .
4. Suscríbase a devoluciones de llamada de marco y estado.
5. Llama al `connect()` y luego al `start()`.

<a id="when-to-use-the-ble-template-instead"></a>

## Cuándo utilizar la plantilla BLE en su lugar

Prefiere la aplicación `eeg-demo` estructurada o el iniciador `eeg-ble` dedicado, cuando quieras:

- una comprobación rápida del entorno para comprobar la compatibilidad con BLE del navegador
- una referencia para el inicio y manejo de estados del transporte
- un punto de partida más sencillo que cablear las devoluciones de llamada desde cero

---

<a id="common-gotchas"></a>

## Problemas comunes

- Si falta `navigator.bluetooth` , es probable que se encuentre en un navegador no compatible o en un contexto no seguro.
- Si el selector de dispositivo nunca aparece, confirme que Bluetooth esté habilitado y que la página se proporcione desde `https://` o `localhost`.
- Si los dispositivos Athena no se pueden decodificar, asegúrese de pasar un `athenaDecoderFactory` respaldado por `@elata-biosciences/eeg-web`.
- Si necesita una ruta de navegador iOS normal, planifique un puente nativo o una estrategia híbrida en lugar de Safari. La guía BLE del navegador aquí asume Bluefy en iOS.
